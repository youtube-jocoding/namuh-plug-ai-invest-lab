# 설계와 실패 정책

## 경계

```text
명시적 거래 일정 + 완료 봉 CSV
  → 전체 데이터 검증 및 해시 고정
  → 해당 시점에 공개된 공통 스냅샷
  → 자기 원장·자기 최근 응답을 붙인 독립 패킷
  → 모든 참가자 동시 호출, 단일 응답 기한
  → 출력 스키마·현금·보유 한도 검사
  → 공통 인프라 오류면 회차 전체 중단
  → 다음 시가 체결 / 갭·부분체결·미체결
  → 단일 트랜잭션으로 체결·원장·회차 완료
  → 공개 가능한 HTML/JSON/CSV
```

코어는 증권사 API와 분리됐습니다. `providers.py`에만 모델 통신이 있고 `engine.py`의 다음 시가 체결은 실제 주문이 아닙니다. DB 한 개는 실험 한 개입니다.

## 예방하는 실수

| 실패 형태 | 예방 또는 처리 |
|---|---|
| 현재 봉의 종가·거래량을 보고 시가 매수 | `available_at <= cutoff`인 완료 봉만 입력 |
| 모델 응답이 빠르면 더 좋은 체결 | 동일 세션 시가, 같은 비용·수량 제한 |
| 초 단위 시세와 소수점 마감 비교로 첫 종목만 만료 | `quotes.py`의 다음 초 장벽 후 공통 수집·제한 재조회 |
| 일부 모델만 402 후 다른 모델은 거래 | 전 모델 체결 전 공통 회차 중단 |
| 크레딧 잔액 확인 직후 다른 앱이 잔액 소모 | 사전 예약 추정에 더해 사후 공통 오류 검사 |
| 재시작으로 유료 호출·거래 중복 | OS 파일 잠금, 회차 ID, 트랜잭션, 미완료 회차 자동 재호출 금지 |
| 이름만 바뀐 다른 모델로 몰래 실행 | 정확한 ID·provider 검증, fallback 비활성 |
| 기록을 수정해 순위를 복원 | 원장·체결·스냅샷·입력 변경 차단; 새 데이터/정책은 새 실험 |
| HTML/CSV에 모델 출력 삽입 | HTML escape, CSV 수식 접두문자 이스케이프 |

다음 초 장벽은 **코드에 공급자가 선언한 시각 정밀도**를 반영한 것입니다. 밀리초·거래소 시퀀스 번호 등 다른 공급자 계약을 쓰면 어댑터와 테스트도 같이 수정해야 합니다. 시스템 시계 동기화와 공급자 시계 편차를 없애 주지는 않습니다.

## 수익률과 거래 가정

- 초기 현금을 분모로 각 시장 수익률을 구하고 같은 가중치로 평균합니다. KRW와 USD 금액을 더하지 않습니다.
- 수수료와 세금은 정수 최소 통화 단위로 올림합니다. 슬리피지는 매수 가격을 올리고 매도 가격을 내리는 방향으로 반영합니다.
- 유동성 한도는 과거 거래량에서만 계산합니다. 해당일 최종 거래량은 사용하지 않습니다.
- 매도 후 매수 순서로 가상 체결을 계획합니다. 부분 매도로 슬롯이 남거나 시가 갭으로 현금이 부족하면 그 모델의 주문 묶음을 모두 거절합니다. 사전 계획한 일부 주문만 실행해 다른 전략으로 바꾸지 않습니다.
- 완료된 주문이 없는 회차도 남깁니다. 모델 의도, 출력 오류, 공통 장애, 미체결을 구분해야 합니다.
- 잔고는 즉시 재사용 가능한 가상 현금입니다. 실제 T+ 결제·매수 가능금액 규칙이 아닙니다.
